# aspynotifications

`aspynotifications` is the domain package for the Notification Service. It
currently implements destination persistence and its CRUD service.

## Package information

| Property | Value |
| --- | --- |
| Package | `aspynotifications` |
| Version | `0.1.0` |
| Python | `>=3.12,<3.13` |
| Source | `packages/aspynotifications/src/aspynotifications` |

Package metadata and dependencies are managed by `aspymgr`. Generated
`pyproject.toml` and requirements files must not be edited manually.

## Architecture

The current destination flow follows the HexaAs separation of service, port,
factory, and adapter:

```text
DestinationsService
        |
        v
IDestinationStorePort
        |
        v
DestinationStoreFactory
        |
        v
LOCALFS | MONGODB adapter
```

| Layer | Location | Responsibility |
| --- | --- | --- |
| Entity | `entities/destination.py` | Defines the persisted destination. |
| Typed endpoint configuration | `config/destination_config.py` | Defines endpoint-specific configuration. |
| Service | `services/destinations_service.py` | Creates, retrieves, lists, updates, and deletes destinations. |
| Port | `ports/destinations_store_port.py` | Defines the persistence contract. |
| Adapters | `adapters/` | Persist destinations in local files or MongoDB. |
| Factory | `factories/destinations_store_factory.py` | Selects the configured store adapter. |

## Destination model

| Field | Type | Description |
| --- | --- | --- |
| `id` | `str` | UUID generated by `DestinationsService` during creation. |
| `name` | `str` | Unique human-readable destination name. |
| `provider` | `str` | Configured delivery provider name. |
| `type` | `email`, `slack_channel`, or `teams_conversation` | Endpoint type. |
| `template` | `str` | Logical template name. |
| `routable` | `bool` | Indicates whether the destination accepts event-supplied recipients. |
| `config` | typed model | Endpoint-specific configuration. |

`Destination` rejects extra fields through `ConfigDict(extra="forbid")`.

Endpoint configuration models are:

| Type | Configuration model | Fields |
| --- | --- | --- |
| `email` | `EmailDestinationConfig` | `type`, `to`, `cc`, `bcc` |
| `slack_channel` | `SlackChannelDestinationConfig` | `type`, `channel_id` |
| `teams_conversation` | `TeamsConversationDestinationConfig` | `type`, `service_url`, `conversation_id` |

## Application operations

`DestinationsService` exposes these asynchronous operations:

| Operation | Description |
| --- | --- |
| `create_destination` | Generates the UUID, verifies unique ID and name, and persists the destination. |
| `get_destination_by_id` | Retrieves a destination by ID. |
| `get_destination_by_name` | Retrieves a destination by name. |
| `list_destinations` | Lists all destinations. |
| `update_destination` | Persists changes to an existing destination. |
| `delete_destination` | Deletes a destination by ID. |
| `ping` | Verifies the configured store. |

## Configuration

Configuration is loaded with `aspyconfig` from these directories:

```text
monoconfig/default/aspynotifications/
monoconfig/<os-user>/aspynotifications/
```

The user-specific directory has higher precedence. The root configuration key
is `aspynotifications`.

Example local-file configuration:

```yaml
aspynotifications:
  destinations_store:
    adapter:
      type: LOCALFS
      config:
        data_dir: ./var/aspynotifications/destinations_store
  destinations_service: {}
```

### Storage adapters

The active adapter is selected through
`aspynotifications.destinations_store.adapter.type`:

| Type | Implementation | Main configuration |
| --- | --- | --- |
| `LOCALFS` | `DestinationsStoreAdapter` | `data_dir` |
| `MONGODB` | `DestinationsMongoStoreAdapter` | MongoDB adapter configuration |

Adapters are registered lazily in
`resources/config/aspynotifications_plugins.yaml` under the
`destinations_store` plugin group.

## Temporary destination test

Until an official input adapter is implemented, use the temporary test runner:

```bash
python tests/create_destination.py \
  --name email-alerts \
  --provider email \
  --type email \
  --template incident-template \
  --destination-config '{"type":"email","to":["alerts@example.com"],"cc":[],"bcc":[]}'
```

The command prints the persisted `Destination` as JSON, including the UUID
generated by the service.
